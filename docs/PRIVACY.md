# 公开仓库隐私规范

公开源码、示例、测试及提交说明均不得包含实际账号、个人邮箱、真实昵称、居住区域、聊天摘录、私人音色标识或实例运维信息。测试中的成员、消息、地址和素材必须明确标为合成案例；地理清洗案例最多使用“上海市”。

虚构项目角色和第三方作者、仓库链接、许可证及固定版本属于公开项目资料，保留必要署名。

## 提交身份

本仓库使用 `124993660+aurorarain@users.noreply.github.com`。GitHub 提供的 noreply 邮箱用于隐藏个人邮箱；该地址中的数字是 GitHub 用户 ID，不是 QQ 号。

```sh
git config user.name aurorarain
git config user.email 124993660+aurorarain@users.noreply.github.com
```

请同时在自己的 [GitHub 邮箱设置](https://github.com/settings/emails) 中确认提供的地址，并启用邮箱隐私与阻止暴露私人邮箱的推送选项。仓库内的说明不会自动修改其他本地克隆的 Git 配置。

## 发布前检查

- 检查暂存区、文件名和提交说明，测试案例不可直接复制真实对话。
- 运行离线回归，并对当前文件与所有可达提交运行密钥扫描。
- 检查作者和提交者邮箱；目录忽略规则不保护已经提交的文件或历史版本。
- 部署及验证文档只保存通用过程和合成场景，不保存实例路径、IP、网址、拓扑、备份时间或日志。
- 音色标识仅从环境变量读取；声音状态只显示是否配置，不返回实际标识。

## 历史重写后的协作

隐私清理保留了历史变更的技术标题，移除了提交正文中的互动叙述，并重写了文件内容与提交邮箱。历史提交标识会随之变化。

其他工作副本应重新克隆。若有未推送工作，先保存并手工检查，再将必要改动应用到新的克隆；不要将旧分支合并或推回，以免重新引入被清除的历史。

重写分支不能清除其他人的克隆、fork、截图或平台缓存。仍可访问的旧提交和引用需要按 GitHub 的敏感数据移除流程另行处理。
